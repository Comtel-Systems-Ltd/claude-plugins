# Reading DipTrace Schematics

## File types

| Extension | Format | Readable? |
|-----------|--------|-----------|
| `.dch` | Binary (`DTSCHEM` magic) | No — ask for an export (below) |
| `.net` | KiCad netlist (S-expression) | Yes — directly, no parser (preferred) |
| `.asc` | DipTrace ASCII (S-expression text) | Yes — via parser script |
| `.xml` | Plugin exchange XML (DipTrace XML format) | Yes — via parser script |

## Getting an export from the user

**Preferred: KiCad netlist** — in DipTrace Schematic, **File → Export → Netlist → KiCad...** producing `<name>.net` next to the `.dch`. Standard S-expression, deterministically sorted (good git diffs), includes RefDes, values, footprints, sheet names, and pin functions. Read it directly — no parser needed. Quirks: net names sanitized (`+3.3V` → `+3_3V`); component values live in the `(components ...)` section, not on net nodes; export also drops a `DC_<name>.eli` library dump (gitignored junk). These `.net` files are **tracked in the hardware repo** — check for an existing one before asking for an export; it may just need regenerating if the `.dch` is newer.

The ControlCard repo has a pre-commit hook (`.githooks/`, `core.hooksPath` set per clone) blocking commits that stage a `.dch` without its `.net`.

**Retired plugin** (uninstalled 2026-07): an "Export XML for Claude" DipTrace plugin once produced full exchange XML (user fields/coordinates/buses) + a custom netmap. Source + settings archived in `plugin-archive/` next to this skill — rebuild with .NET Framework `csc /target:winexe /r:System.Management.dll` and drop the folder into `C:\Program Files\DipTrace\Plugins\Schematic\` if full-XML export is ever needed again. Manual alternative: File → Export → DipTrace XML. No on-save hook exists in DipTrace — all exports are manual menu actions.

Fallback: **File → Export → DipTrace ASCII...** produces a `.asc`.

## Parsing

`.net` (KiCad) needs no parsing — Read/Grep it directly. For a `.asc` ASCII export or a plugin exchange XML, run the parser next to this skill:

```powershell
& "$env:USERPROFILE\.claude\skills\diptrace\parse-diptrace.ps1" -In "<export file>" -Out "<scratchpad>\netmap.txt"
```

Auto-detects `.asc` vs XML. Output format (same as the plugin's `.netlist`):

```
=== PARTS (42) ===
U1: PIC18F57K42-I/PT = PIC18F57K42 [48 pins]
=== NETS (57) ===
NET[0] +3V1: C1.1(0.1u) U1.7[VDD](PIC18F57K42) U2.8[VDD](FM25V05) ...
```

`RefDes.PinNumber[PinName](Value)`. Grep the netmap for rails, CS lines, pullups, etc. — usually no need to touch the raw export again.

## Verification & gotchas

- **XML pin-name resolution is best-effort** (resolves pin Name/PadNumber via the embedded `<Library>` section, keyed by `ComponentStyle`). On first use with a real export, sanity-check one known net (e.g. VDD pin of the MCU) against the schematic. The `.asc` path is battle-tested; if XML output looks off, ask for an ASCII export and compare.
- Multi-part components (`ComponentPart` attribute) may mis-resolve pin names in the XML path — pin numbers fall back to index+1 when the library lookup misses.
- `.asc` nets reference parts by file order; the parser relies on each pin's `NetNumber` instead (self-contained, robust).
- Net names like `Net 0`, `Net 27` are unnamed autogenerated nets — still real connections.
- DipTrace format specs (PDF) live in `C:\Program Files\DipTrace\Docs\` — `DipTraceXML_Schematic_En.pdf`, `DipTraceXML_CompEdit_En.pdf`. Extract text with `pdftotext` (in Git's mingw64 bin) if a corner of the format needs checking.
- Off-board context: a schematic page only shows its own board. Nets ending at connector pins (e.g. `J104.3[P3](to Motherboard)`) continue on another board's schematic — ask for that board's export before making claims about the full signal path.
- **BOM files (`* - BOM.csv/.xlsx`) in the hardware repos are manually exported and often stale.** Don't trust them over the netlist — compare their mtime against the `.dch` first, and prefer part values/footprints from a fresh `.net` export. For sourcing fields (Digikey P/N etc.) not in the netlist, ask the user to confirm or re-export the BOM.
